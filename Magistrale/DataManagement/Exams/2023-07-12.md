**Problem 1**
> The *separation degree* between researcher A and researcher B (different from A) is 1 if they have collaborated, and is 2 if both of them have collaborated with a third researcher C. Let R(A,B) be a relation (therefore, without duplicates) storing all the tuples ⟨r, s⟩ such that researchers r and s have collaborated. Obviously, R is symmetric. 
> We know that (i) no researcher has more than 300 collaborations, (ii) associated to R there is a clustering B+-tree index on attribute A whose cost for retrieving the first tuple of R with a certain value for A is 4 page accesses, (iii) every page has space for 500 tuples of R, and (iv) the buffer has 100 frames available. 
> Considering the query Q that, given a specific researcher x, computes the set (therefore, without duplicates) of researchers with whom x has separation degree less than or equal to 2, illustrate the most efficient algorithm you can think of for answering Q, and tell which is the cost of the algorithm in terms of number of page accesses.

This is the first part of the query Q
```sql
select B
from R
where A = x

union

select r2.B
from R r1 join R r2 on r1.B = r2.A
where r1.A = x and r2.B not = x
```

Given that no researcher has more than 300 collaborations, means that selecting over a single researcher will have a single page as the result.

The first part of the query will take just 4 page accesses, and we'll keep the result of the projection in buffer.
For the second part We will find all of the pages of the collaborators calculated before, which has cost $4*300 = 1.200$ page accesses, and from it we can select out all tuples that have x as B.
the total cost is $5 + 5*300 = 1.505$ page accesses.

**Problem 3**
> A schedule S is called parsimonious if it contains only write actions and no element of the database is used by more than two actions in S. Prove or disprove that every parsimonious schedule is conflict serializable if and only if it is view serializable.

We can rapidly close the conflict -> view, given that a parsimonious schedule is still a schedule
To prove or disprove the statement, we just need to check the implication view -> conflict.
Given a view-serializable schedule S, we know that it will have a last-write set equal to the serial schedule S, and we won't have any read-froms. Now we can consider a generic schedule: ... wi(X) ... wj(X) ... that is view-serializable
wj(X) will surely be on the last-write set, since no element can be used by more than two actions in S, and for this reason the action order will need to be respected on the serial schedule. 

Let's suppose that it's not conflict-serializable. This means that there doesn't exist any serial schedule with the same set of conflicts. But given the fact that there doesn't exist any other serial schedule different from the one view-equivalent to S (or else, the final write set would be different), we can see that the conflict set is respected.

**Problem 4**
> Let R(A,B,C) and S(D,E) be two relations, each stored in a heap. A tuple t of R is said to be a lower k-match with S if there are at least k tuples of S whose value in the attribute D is equal to the value of t in the attribute C. Let M be the number of buffer frames available, let Q be the query that, given a value for k, computes all the tuples in R that are lower k-matches with S, and consider the following questions. 
> 4.1 Describe the conditions under which we can process Q using the one-pass, the two-passes, and the block-nested loop method, respectively.
> 4.2 For each of the methods mentioned above, illustrate the corresponding algorithm and tell which is the cost of such algorithm in terms of the number of pages of R and S.

The SQL query for Q is:
```sql
select A,B,C, count(*)
from R join S on C = D
group by A, B, C
having count(*) >= k
```
We won't need to actually join the tuples together, as it's a costly operation

If $B(S) \le M - 2$ we can do a one-pass algorithm:
1. Load B(S) completely in memory
2. Load B(R) in the buffer, one by one.
3. For each tuple in R, count the number of tuples such that C = D. 
4. If not smaller than k, then copy the tuple of R in the output buffer
The cost is $B(R) + B(S)$

If $B(R) + B(S) \le M(M-2)$ we can do a two-pass algorithm:
1. Create $M_R$ and $M_S$ sublists, over the search keys C and D.
2. For each tuple t check if there are at least k tuples in S with C=D
Cost is $3(B(R)+B(S))$

We can consider always the block-nested loop algorithm:
1. Load B(R) in M-2 blocks
2. For each block load one page of S
3. Scan the entirety of S, using the output buffer to count the appearances of C = D
4. Once the relation S is finished scanning, we copy in output only the tuples having count >= k
Cost is $B(R) + (B(R)/(M-2) * B(S))$

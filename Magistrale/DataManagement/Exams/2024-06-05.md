**Problem 3**
> Consider the relations R(A,B,==C==,D,E,F) and S(==A==,B,G,H), where R contains 260.000 tuples (20 tuple per page), V(R,A) = 1000, there is a hash-based index for S on the integer attribute A, there is a B+-tree index for R on attribute A, and the buffer has 205 free frames available. Consider the query type Q (where x and y are integer constants): 
```sql
select A,B from R where A ≥ x and A < x + 20
union
select A,B from S where A = y
```
> for which we remind the reader that the SQL union operator performs the union of two sets (or bags) by eliminating duplicates in the result. Illustrate the algorithm you would use to answer queries of type Q, and tell which is the cost of the algorithm in terms of number of page accesses.

We consider the first query. We need to select all tuples having attributes in a range $R[A] \in [x,x+20)]$ which equates to approximately $20*V(R,A) = 20.000$ values. Considering That there is a B^+ - tree index on R over A, we need to get te cost of finding the first value. To do so we calculate the height.
B+ trees have their data entries 66% full, and their index entries 75%. Given 120 attr/pages, each page will contain at max $60*0,75\% = 45$ children. Given that we assume that R is a heap, we will have 260.000 data entries to put in leaves, which are 66% occupied. Each leaf contains $60*0,66 = 39$ data entries, we will have $260.000/39 = 6.667$ leaves. So the cost of accessing one element is $\log_{45} 6.667 = 3$ page accesses + 1. We consider data entries to be linked together and ordered with key A. 
We will have $t(R)/V(R,A) * 20 = 5200$ tuples that satisfy the selection query, which at worst will be on different pages on the data file. On the data index files 5200 data entries fit in 140 leaves. 
The cost is then $3+ 140 + 5200 = 5343$ page accesses 

The algorithm will be to load the bucket with A = y (which has cost 1 + 1 for accessing the data file) , load the correct tuples of the relation R (which completely fit in buffer) and do the set union in buffer in a one-pass.
Cost will be 2 + 5343 page accesses

**Problem 4**
> Consider the relations R(==A,B,C==) and S(A,B,C), where (i) R has ⟨A,B,C⟩ as the key and contains 100.000 tuples stored in a heap with 1.000 pages; (ii) S contains 12.000 tuples stored as a heap of 120 pages. Our buffer has 100 free frames available, and we have to compute the difference between R and S (i.e., R - S), with the goal of maximizing efficiency, obviously in terms of number of page accesses. Illustrate the algorihm you would choose and tell which is its cost in terms of number of page accesses.

We have two different routes to follow. Given that we have 100 frames, we check if we can do a set difference in two passes. $B(R) + B(S) \le M(M-1) = 1120<9900 \square$
We can also do a block-nested loop over blocks of R (and not of S, since S is a bag), and for this we'll check both possibilities:
- For 2-pass we have 3(B(R)+ B(S)) = $3360$ page accesses
- For block-nested loop we have $B(R) + (B(R)/M-2 * B(S)) = 2320$ 
Block nested loop is more efficient.

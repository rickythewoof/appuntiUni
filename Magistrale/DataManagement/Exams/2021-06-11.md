**Problem 3**
> Let R(A, B) and S(C, D) be two relations with B(R) and B(S) pages, respectively, where R is stored in a file sorted on B, and S is stored in a heap. Let us denote by σ(R, S) the operator computing the following result:
> σ(R, S) = { x ∈ R[A] | for all y such that (x, y) ∈ R, we have that (x, y) ∈ S }
> Assuming that M > 2 free buffer frames are available, describe the most efficient algorithm that you think we can use to compute the result of σ(R, S), and tell which is the cost (as a function of M , B(R) and B(S)) of such algorithm in terms of number of page accesses.

This asks for a selection on an equality. Basically it's asking this query:
```sql
SELECT A
from R
where exists (SELECT * from S where R.A = S.C and R.B = S.D)
```
Considering this, we know that we cannot adopt a simple block-nested loop. Not having order on S, a linear scan wouldn't be sufficient. For this reason we adopt this strategy:
- We do a multi-pass sorting on R over the attribute A
- We do a multi-pass sorting on S over the attribute C
- We do the merge & selection phase using $M-1$ buffer frames for the input, and $1$ frame for the output

We want to have $M_R$ sublists of R. Using $M$ frames, we can do that by considering that at pass 0 we'll have $B(R)/M$ sublists. After that, we will have to consider that $B(R)/(M-1)^K \le M_R$. This means that the passes needed to do this will be $K = \log_{M-1} B(R)/M_R$. $P_R$ at this point will be $1+K$ \[...]

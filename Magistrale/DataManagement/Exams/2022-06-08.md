**Problem 3**
> Let τ indicate the ternary operator such that τ(R, S, T ) = R ∪s (S −T ), where R, S and T are three relations with the same schema and without duplicates, ∪s indicates set union and − indicates set difference. 
> 	3.1 Design and describe in detail a two pass algorithm that, given R, S, T , each one stored as a heap, computes τ(R, S, T ). 
> 	3.2 Tell under which condition the algorithm can be used and illustrate the cost of the algorithm in terms of number of page accesses.

1. In the first pass we create sublists of S and T and we compute the difference, such that $M_R + M_S + M_T \le M-1$, being $\displaystyle M_R = (M-1)\frac{B(R)}{B(R)+B(S)+B(T)}, \ M_S = (M-1)\frac{B(S)}{B(R)+B(S)+B(T)}, \ M_T = (M-1)\frac{B(T)}{B(R)+B(S)+B(T)}$ . This can be done iff $B(S)/M \le M_S$ and $B(T)/M \le M_T$.
2. In the second pass we use the buffer frames as follows: $M_S$ frames for the sublist S, $M_T$ frames for the sublist T, $M_R$ frames for R and $1$ frame as output.
3. Find the smallest tuple t between the three:
	1. if $t \in R$ add in output and ignore all occurrences in $S$ and $T$.
	2. if $t \notin R$:
		1. if $t \in S$ and $t \notin T$ add $t$ in output 
		2. else ignore all occurrences of $t$

This algorithm has cost: $3(B(R)+B(S)+B(T))$ 

**Problem 4**
> Consider the relations 
> - Restaurant(==code==,citycode,seats) with 18.000.000 tuples
> - City(==citycode==,region,country) occupying 195 pages
> each page with 100 tuples (keys are highlighted). We assume that $V(City, country) = 150$, which means that 150 values are in the attribute country, that each value (regardless of the type) requires the same number of bytes and that we have 200 frames available in the buffer. Consider the query:
```sql
> select country, sum(seats)
> from Restaurant r, City c 
> where r.citycode = c.citycode
> group by country
> ```
> and describe the algorithm you would use to execute the query, illustrating the number of page accesses required by the execution of the algorithm.

the relation Restaurant occupies 180.000 pages, while City requires 195 pages. We need to do a Join, and since we have 200 frames, $B(City) \le M$ means that we can do the join in one pass. We can use 195 frames for City, 1 frame for Restaurant, 2 frames for the join and 1 for the group. Let's check that 1 frame is enough for all of the grouping:
100 tuples /page, 3 values per tuple $\rightarrow$ 300 val/page $\square$.

1. We load the entire City relation in buffer
2. We load each page of Restaurant
3. Find the smallest tuple $t$ over the attribute $citycode$ and do the join if exist in both places.
4. Select country, seats from the joined tuple
5. Update the appropriate tuple in the grouping buffer with the data
Cost is $B(r) + B(c)= 180.195$ pages
